# data/

This directory is not committed to Git (see `.gitignore`) — it accumulates locally-downloaded COCO images,
locally-generated AI images, and various intermediate manifests across the project's history. This file
documents provenance and how to regenerate what the **final** result set (`docs/FINAL_RESULTS.md`) needs; it is
not an inventory of every directory that may exist here from earlier exploratory phases.

## What the final pipeline needs

- **`data/content_matched/`** — the 60 matched content identities: `real/` (60 COCO photographs), plus one
  subdirectory per generator (`sd15/`, `sdxl/`, `pixart_dit/`, `amused/`), and `manifest.csv` tying them
  together by `content_id` and shared human caption. Regenerate with `scripts/build_content_matched.py` (real
  images + aMUSEd) and the per-generator `scripts/generate_*.py` scripts (SDXL, PixArt-Sigma DiT).
- **`data/final_validation/`** — manifests for the final robustness/AI-edit validation phase (transforms are
  applied on-the-fly from the paths in `content_matched/`, not stored as separate image files). Regenerate with
  `scripts/build_final_validation_manifest.py` + `scripts/build_final_validation_combined_manifest.py`.
- **`data/ai_edit_scaled/`** — the 60-content img2img edit-strength continuum. Regenerate with
  `scripts/generate_ai_edit_scaled.py`.

## Real images

Real images are 60 photographs from **COCO 2014 val** (`coco2014_val2014`), referenced by COCO image id in
`data/content_matched/manifest.csv`. `scripts/build_content_matched.py` downloads only the specific 60 images
needed (not the full COCO dataset) via the standard COCO API/URLs. COCO images are licensed by their original
photographers under Creative Commons licenses (see https://cocodataset.org/#termsofuse) — this project does not
redistribute the images themselves, only their ids and the derived scalar feature values.

## Generated images

Every non-real image in `data/content_matched/` was generated by this project, from the same human COCO
caption as its matched real counterpart, using the generation script named after that generator
(`scripts/generate_sdxl.py`, `scripts/generate_pixart_dit.py`; aMUSEd is generated inline by
`scripts/build_content_matched.py`). Exact frozen configuration (steps, guidance, scheduler, seed policy) for
each generator is documented in that script's own docstring and in the corresponding preregistration under
`docs/research_history/`.

## Why generated images are not committed

They are regenerable byte-for-byte (deterministic seeding, `seed = hash(generator:content_id)`) from the
manifest + generation scripts, and committing ~100MB+ of PNGs to Git for a redistribution purpose the derived
feature tables already serve is not worth the repository weight. A small representative QC contact sheet is
committed instead where relevant (e.g. `results/stage_decomposition/pixart_dit_qc.png`).

## Model weights

Not stored here or anywhere in this repository — see `docs/REPRODUCIBILITY.md` for the Hugging Face repo ids
each generator/probe pulls from automatically on first use.
